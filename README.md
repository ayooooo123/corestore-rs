# corestore-rs

[Corestore](https://github.com/holepunchto/corestore) 7 for [hypercore-rs](../hypercore-rs): many
cores in one storage directory, named cores derived from one primary key, and one replication
stream for all of them.

```rust,no_run
use corestore::{Corestore, GetOptions};

# async fn demo(mux: protomux::Mux) -> Result<(), Box<dyn std::error::Error>> {
let store = Corestore::open("./store".as_ref())?;
let channel = store.namespace("channel-1");
let feed = channel.get(GetOptions::name("feed")).await?; // same key as JS for the same primary key
feed.append(&[b"first".as_slice()]).await?;
store.replicate(&mux); // every open core, plus any stored core the remote asks for
# Ok(()) }
```

- **Keys**: `namespace(name)` and `create_key_pair(name)` derive exactly as JS corestore
  (`generateNamespace`, `createKeyPair`), so the same primary key, namespace path and name give the
  same core key. `fixtures/keys.json` is generated by npm corestore 7.16.1 (`tests/js/peer.js keys`).
- **Open by discovery key**: `replicate()` pairs on every `hypercore/alpha` open. When the remote
  asks for a discovery key that is stored here but not open, the core is opened and attached to
  that connection; unknown keys are rejected.
- **Watch**: `watch()` yields each core as it opens (JS `store.watch`).
- **Sessions**: `session()` opens an independent default-namespace scope; `namespace()` opens an
  independent scope in the derived namespace. Closing a scope closes only its sessions. Closing
  the root store closes all scopes and storage. Set `GetOptions::exclusive` to await an exclusive
  lease; leases can be moved between sessions on the same physical core.
- `purge()` deletes a stored core unless it has active sessions; `list()` lists stored cores.
- `set_inflight_range((min, max))` changes open cores and the default for later opens; an
  explicit `GetOptions::inflight_range` selects the window for that open.

- **Storage**: everything lives in hypercore-storage's own rows, so the npm corestore 7.16.1 can
  open the same directory: the primary key is the store head's `seed`, `namespace`/`name` aliases
  are the alias rows that point at a discovery key, `list()` is the discovery-key index, and
  `create_group`/`notify_group` use the group and group-update rows. `set_alias` and
  `namespace_raw` write and read those rows directly.
- Named aliases are persisted, and `storage_infos` reads stored heads without opening cores.
  `open_read_only` rejects writes. `close` invalidates existing handles and releases storage.

Not ported: groups and group notifications, `staticify`, `suspend`/`resume`, and `audit`.

## Tests

`cargo test`; `cargo test -- --include-ignored` also runs `tests/interop.rs` against npm corestore
(needs `npm install` in `tests/js`): JS downloads three Rust cores that are only stored, not open,
and Rust downloads a JS core.
